# Dr. AI v1.0.0-beta.1 Release Notes

Prepared: 2026-07-06

Status: prepared locally with Tencent staging same-origin web/API deployment
verified. Android release signing now requires a local upload key instead of
debug signing. The tag `v1.0.0-beta.1` has not been created.

## Beta boundary

Dr. AI v1.0.0-beta.1 is an invited, synthetic-data-only, non-clinical beta.
It is intended for workflow validation and demonstration with seeded fixtures.
Do not enter real patient data.

## Included in this beta

- Email/password authentication, role routing, secure refresh, logout, and
  neutral wrong-role/cross-patient denial.
- Doctor web dashboard and patient mobile dashboard with seeded synthetic
  content.
- Doctor patient-management workflow for assigned-patient search, profile,
  records, medications, doctor notes, demo upload preparation, simulated
  assessment, recovery-plan editing, plan activation, and specialist
  consultation request.
- Patient Today tasks, completion tracking, demo-only local notification shell,
  educational Ask Dr. AI chat, and consultation status readback.
- Server-side DeepSeek educational-chat proxy with local/test safe fallback,
  red-flag detection before any LLM call, rate limiting, and metadata-only
  audit/storage behavior.
- Beta support surface with privacy notice, consent checklist, account deletion
  request preparation, feedback draft preparation, and known limitations.
- Mark-only Dr. AI logo artwork for in-app branding, web/PWA icons, Android
  launcher icons, and iOS app icons. The icon artwork excludes the `Dr. AI`
  wordmark.
- Local accessibility, text-scaling, contrast, validation, dependency, and
  log-hygiene hardening coverage.

## Not included

- Real clinical assessment, real model inference, DeepSeek fine-tuning, or
  clinical claims.
- Real patient data ingestion, raw record/image upload completion, or sending
  patient-owned content to DeepSeek.
- Billing, appointments, video/voice consultation, analytics expansion,
  production monitoring changes, or administrator audit-event reads.
- TestFlight upload, Android closed-testing upload, production web deployment,
  tester invites, release tag creation, or account-setting changes without
  explicit release approval.

## Known limitations

- Simulated assessment results are deterministic fixture outputs and must be
  shown as research simulation only.
- Demo upload currently prepares metadata and a signed URL shape; real COS
  upload completion remains approval-gated.
- The local feedback and account-deletion controls prepare local drafts only.
  They do not send messages, delete data, or alter accounts.
- Android release signing is configured to require an ignored local
  `android/key.properties` file and upload keystore. No keystore/password is
  checked in, so Play Console artifacts cannot be produced until those local
  credentials exist.
- Tencent staging was refreshed after explicit approval on 2026-07-06 and now
  serves both the Flutter web app and refreshed API from
  `https://dr-ai.43.132.169.195.sslip.io`. `/health`, `/api/*`, root web, and
  `/beta-support` passed post-Caddy checks, and the credentialed staging smoke
  passed after the same-origin web deployment.
- Computer access for personal beta testing should use the HTTPS staging web
  app as a browser-installed web app/PWA. Native desktop packaging is not part
  of this beta pass.
- A local Android debug APK for personal-device testing was built against the
  staging API origin at
  `apps/dr_ai_app/build/app/outputs/flutter-apk/app-debug.apk`.
  Current SHA-256 after the mark-only logo refresh:
  `c331b485fa3d04e2fb9030a5ba2ee5769919f6343dfbf10d5fcef4fe217c55aa`.
- Non-secret public-route screenshots were captured under
